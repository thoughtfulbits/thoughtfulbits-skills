# Atlas workspace setup

## Target user and task

A first-time operations lead has already created an Atlas account with a verified work email and company domain. They want to reach a usable workspace and create their first project as quickly as possible.

## Current flow

### Screen 1 — Welcome

The page explains Atlas in three paragraphs. The primary button is **Start workspace setup**. A secondary **Import an existing workspace** link opens separate documentation. There is no resume-later option.

### Screen 2 — Company details

The user must complete all six fields before **Continue** becomes available:

1. company name, even though Atlas already derived it from the verified company domain;
2. industry, selected from a 70-item menu;
3. team size;
4. a 500-character description of the company's operating objective;
5. company logo upload; and
6. time zone, even though the browser and account profile agree on it.

The company description will appear only as editable workspace profile copy. A logo can be added later. Validation preserves entries, but errors appear only after **Continue**.

### Screen 3 — Team setup

The user must re-enter their own verified work email and select **Workspace owner** from a role menu. They must also enter a colleague's email and choose that colleague's role. Atlas describes invitations as required setup even though workspace settings supports invitations later. **Continue** sends the colleague invitation immediately; there is no preview or skip action.

### Screen 4 — Review and create

The page repeats every answer. **Edit** links return to each prior screen but discard changes made on later screens. The user must check **I confirm this workspace information is accurate** and select **Create workspace**. The checkbox is a consequential user attestation and must not be generated or selected automatically.

Creation takes 5–15 seconds without progress detail. Success redirects to an empty workspace whose only action is **Create first project**. The setup answers do not prefill that project.

## Accessibility and safety provisions

- Controls use native HTML elements with visible labels and keyboard focus.
- Validation messages are associated with their fields.
- The layout reflows at 320 CSS pixels.
- Account identity, invitation recipients, role assignment, and the final attestation must remain user-reviewed decisions.
- Atlas may propose editable descriptive copy, but it may not silently submit or invite anyone.
